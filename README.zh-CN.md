## 🌟 为什么需要本协议？（AI 编程的致命痛点）

在多轮长对话中，随着代码库复杂度的攀升，几乎所有 AI 编程助手（Claude、Codex、Gemini、GPT）都会不可避免地将项目带入泥潭：
1. **目录污染严重**：测试脚本、临时打包中间件、日志和未脱敏的调试数据随手甩在项目根目录，极易被手滑提交进 Git；
2. **“屎山”补丁架构**：遇到冲突或缺陷时，AI 习惯治标不治本——在已经上千行的臃肿组件里继续堆砌 `if (isSpecialCase)` 布尔标记、强加 CSS `!important` 覆盖、用全局变量穿透，导致代码急剧劣化；
3. **自欺欺人的“伪回退”**：当要求 AI 回退错误改动时，AI 经常在已经损坏的代码上再写一层逆向补丁充当回退，越改越乱，引入连锁次生灾害；
4. **会话失忆与重蹈覆辙**：新开一个对话窗口后，AI 对历史教训一无所知，反复提出用户已经严厉批评并明确否决过的错误方案。

**`captcha-clean-workspace`** 将大型多平台生产级项目在血与火中验证的工程方法论，沉淀为一套强制 AI 执行的刚性协议。它强力约束 AI 执行**大本营物理隔离、工作树自洽开发、高内聚解耦、可验证交付与负向知识归档**。

## 🏛️ 工作区五大治理支柱 (The 5 Pillars)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   CAPTCHA 工作区物理双层拓扑架构                       │
├────────────────────────────────┬───────────────────────────────────────┤
│       版本受控源码区           │         本地私有大本营 (Local/)       │
│  (100% 纯净、极简、面向提交)   │       (100% 忽略 Git 的私有工作区)    │
├────────────────────────────────┼───────────────────────────────────────┤
│  ├── src/                      │  ├── cache/      (依赖/工具链软链接)  │
│  ├── package.json              │  ├── artifacts/  (已验证安装包/产物)  │
│  └── .worktrees/               │  ├── evidence/   (反汇编/日志/测试凭证)│
│      ├── feature-a/            │  ├── docs/       (交接手册/长期规范)  │
│      │   └── WORKTREE.md       │  └── scratch/    (一次性测试，用完即清)│
│      └── feature-b/            │                                       │
└────────────────────────────────┴───────────────────────────────────────┘
```

### 支柱 1：大本营物理隔离规范 (`Local/` 范式)
项目根目录只允许保留核心业务源码与必要配置文件。**所有不进 Git 的大体积资源、第三方依赖缓存、编译产物、运行态日志与一次性排查脚本，一律收敛入本地私有大本营 `Local/` 目录**。子模块通过 Directory Junction 或 Symlink 挂载，彻底根除根目录垃圾泛滥与误提 Git 的风险。

### 支柱 2：工作树自包含隔离生命周期 (`.worktrees/` 标准)
**绝对严禁直接在主分支（`main` / `master`）上做实验或多任务混杂修改**。
所有特性分支与重构必须在隐藏目录 `.worktrees/<task>/` 下展开。每个工作树在创建的第一秒必须确立 `WORKTREE.md`，内聚声明：任务边界、不可破坏的架构不变量、推进事实日志与交付门禁；退役时必须通过 `git worktree remove` 正规注销。

### 3. 防屎山高内聚解耦架构 (Anti-Slop Architecture)
- **纯净门面模式（Facade <= 300 行）**：主调度中心/插件入口严格限制行数，仅做请求分发，严禁内联长篇业务；
- **高内聚自治领域服务**：文件 I/O、网络下载、硬件交互等独立自治；
- **互斥状态物理拆分（实例卡片范式）**：当组件存在多个互斥且复杂的运行状态时，**坚决拆分为独立的单一职责子组件**，由外层容器负责平滑过渡，严禁通过布尔 flag 堆砌补丁；
- **强类型单一契约**：跨模块、跨端通信必须有强类型接口守卫，严禁隐式 `any` 和 `as unknown as Type` 强转。

### 4. 闭环可验证交付与干净回退纪律
- **闭环交付五部曲**：修改源码 -> 静态类型检查 -> 构建同步 -> 真实环境拉起安装 -> 取据确认。证据确凿前，严禁宣称“已修复”；
- **物理基线回退**：回退必须是通过 `git checkout <baseline>` 物理回到已知健康的 Commit；**严禁在问题代码上做差异补丁当作回退**；
- **源码 vs 产物绝对红线**：严禁直接手改任何编译生成物（`dist/`、`bundle.js`），所有修改必须源于源码。

### 5. AI 智能体无痛接手与负向知识库
会话交接手册（`AGENT_HANDOVER.md`）不仅记录“做对了什么”，**必须专门设立章节记录“用户明确批评否决过的错误方案（负向雷区）”**。新接手的 AI 开工前必须执行只读自检 SOP，通读避坑指南，确保零信息差接手，绝不重复踩坑。

## 🚫 借口对抗与红线警报 (Red Flags)

当 AI 脑海中冒出以下借口时，必须**立即叫停并纠偏**：

| AI 的妥协借口 | 真实情况与正确做法 |
| :--- | :--- |
| *“我先把这个测试小脚本临时扔在根目录，测完再删。”* | **违规。** 必须扔进 `Local/scratch/`，或者测完当场删除，根目录绝不留杂质。 |
| *“这个组件有 1000 行了，我就再加一个 `if (isNewMode)` 方便省事。”* | **违规。** 严禁堆砌屎山代码！必须从架构根因解耦，拆分为自治领域组件。 |
| *“这就是个小改动，不需要开独立的 worktree 了。”* | **违规。** 只要涉及核心链路或破坏性试验，一律去 `.worktrees/` 隔离开发。 |
| *“我写个逆向补丁把报错的逻辑改回去，效果是一样的。”* | **违规。** 这叫掩盖漏洞打补丁！必须直接物理 checkout 原始健康基线。 |
| *“我已经把源码改好了，任务完成了。”* | **违规。** 必须经过类型检查、正式构建并在真实运行态确认证据后方可交付。 |
| *“我觉得这个按钮换个圆角或者字体看起来更帅。”* | **违规。** 严禁任何自作主张的“微创新”！有既有成熟样式必须 100% 源码级对齐。 |

## 🚀 安装与使用指南

### 作为 Antigravity / Trae / Codex 全局技能安装
将本仓库克隆至你的全局 AI 技能目录：
```bash
# Antigravity 全局路径
git clone https://github.com/CAPTCHAAAAA/captcha-clean-workspace.git ~/.gemini/config/plugins/captcha-clean-workspace

# 或直接使用内置 skill 目录
cp -r skills/captcha-clean-workspace ~/.gemini/config/skills/
```

### 在任何新项目中一键初始化
将本仓库的 `scripts/init-clean-workspace.ps1` 放入任意新工程根目录并运行：
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\init-clean-workspace.ps1
```
它将自动为你创建：
- 标准的 `Local/` 大本营目录树（`cache/`, `artifacts/`, `evidence/`, `docs/`, `scratch/`）；
- 自动写入 `.gitignore` 防止私有大本营误提；
- 建立 `.worktrees/` 隔离开发目录。

### 在日常对话中唤醒
只需对你的 AI 助手说：
> *“按照 captcha-clean-workspace 规范初始化这个项目”*  
> *“为这个功能在 .worktrees 中建立标准的隔离工作树”*  
> *“遵循防屎山架构，将这个臃肿的巨石模块进行门面解耦”*

AI 将自动加载本协议并受到全套刚性工程纪律的制导。
